# PROJECT CHARTER: OFFLINE BIBLE ENGINE
### Codename: HV-Bible

> This document is the **single source of truth** for the HV-Bible project. It is a living charter — updated after every architecture decision session. Paste this into any coding agent (Copilot, Antigravity, Claude, etc.) as project/system context before any implementation work begins. It defines the non-negotiable core only — UI, navigation, login, and networking code are downstream decisions and out of scope for this charter.

---

## 1. Mission Statement

Build a deterministic, offline-first Bible navigation engine for iOS and Android that resolves a pastor's spoken verse reference to on-screen text in under 200ms from the end of the utterance. The core must be thread-safe, memory-safe by construction, and free of garbage-collection pauses or unpredictable latency spikes.

The app functions as a **radar gun for Bible references** — it listens continuously without recording, discards 99.9% of all spoken audio in real time, and reacts only when it detects the precise pattern of a book name, chapter, and verse number.

---

## 2. Non-Negotiable Engineering Principles

- **Zero-copy cold path.** Verse text is `mmap`'d directly from disk. No deserialization or heap allocation on the lookup path.
- **Compile-time canonical structure.** Book IDs, names, and chapter/verse counts for the reference versification scheme are baked into the binary via a build script — never parsed from JSON/TOML at runtime.
- **Panic-free hot path.** `get_verse` and `resolve_text` must never panic on malformed or adversarial input. Every failure mode returns `Result<T, EngineError>`. `.unwrap()`/`.expect()` are banned in `bible-core` and `bible-asr` outside of tests — enforce with `#![deny(clippy::unwrap_used, clippy::expect_used)]`.
- **No async runtime in the core.** `bible-core` and `bible-asr` must not depend on `tokio`, `async-std`, or any executor. Threading is `std::thread` + lock-free channels (`crossbeam-channel` or `flume`) only. This keeps the audio pipeline's scheduling deterministic. (Networking/download-manager code, if and when it exists, lives outside this charter's scope and outside these two crates.)
- **No recording, ever.** Audio data exists only in a volatile in-memory ring buffer. It is never written to disk, never persisted, and is overwritten continuously by new samples. If the process is killed, all audio vanishes instantly.

## 4. Data Architecture (Cold Path)

### 4.1 Canonical Index — compile-time, universal, embedded

A `phf::Map` generated by a `build.rs` script (via `phf_codegen`, emitting a `.rs` file into `OUT_DIR` and pulled in with `include!`) maps `(BookId: u8, Chapter: u16, Verse: u16) → GlobalVerseIndex: u32`. This mapping is identical across every translation and is compiled directly into `bible-core`.

This index does **not** map to a byte offset. It can't — verse text length varies by translation. The `phf` map gets you to a *global verse index* (0..~31,102, per the Protestant reference versification).

**Versification Decision (Settled):** The project uses the **Protestant canonical 66-book, 31,102-verse** scheme (KJV/NIV/ESV alignment). Translations that diverge (Orthodox additional books, Hebrew Psalm numbering, Joel/3 John/Malachi boundary differences) are handled via a small exception-mapping table in `bible-datagen` — never by changing the compiled-in index.

### 4.2 Per-Translation Offset Table — travels with the data pack

Each downloadable translation ships two files:
- `{code}.bible.bin` — `rkyv`-archived verse text records
- `{code}.offsets.bin` — a flat `u64[]` table: `GlobalVerseIndex → byte offset` within the `.bible.bin` file, generated by `bible-datagen`

This table is **not** compiled into the app — it's translation-specific and must be addable post-launch without a recompile.

### 4.3 Runtime Access

- Verse records use `#[derive(rkyv::Archive, rkyv::Serialize)]`. Access on the hot path is via `rkyv`'s unchecked zero-copy accessor — but only after a one-time validation step.
- **Validate before trusting.** Verify a BLAKE3 checksum before touching the bytes with an unchecked accessor. Failure → `EngineError::CorruptDataPack`. Skipping this turns a bad download into undefined behavior.
- **Lifetime honesty.** A byte slice borrowed from an `Mmap` cannot be `'static`. Hold `Arc<Mmap>` and use the `yoke` crate to bundle the owner with data borrowed from it. If `unsafe` lifetime extension is used instead, it must be documented inline.
- Translation registry: `Arc<RwLock<HashMap<TranslationCode, LoadedTranslation>>>`. Switching translations is an O(1) `Arc` swap.
- **Format versioning.** Every pack carries an explicit `u32` version header. Mismatch → `EngineError::UnsupportedPackVersion`, never a raw cast.

### 4.4 Data Pack Contents

| File | Format | Contents |
|------|--------|----------|
| `{code}.bible.bin` | rkyv archive | Archived verse text records |
| `{code}.offsets.bin` | Flat `u64[]` | GlobalVerseIndex → byte offset |
| `{code}.aliases.bin` | rkyv | Per-language alias tables |
| `{code}.metadata.json` | JSON | Name, copyright, version, checksum |

Data packs are downloaded assets — never embedded in the app binary. Only the canonical `phf` structure index and compiled-in language alias tables ship inside the binary itself.

## 5. Voice & ASR Pipeline (Hot Path)

### 5.1 The Ephemeral Ring — Privacy-by-Design

The app does **not** record. Audio is fed into a volatile circular ring buffer in RAM (~10 seconds of 16kHz PCM mono = ~320KB). As new samples arrive, the oldest are overwritten. There is no file write, no disk flush, no OS buffer that persists beyond the current process lifetime. Killing the app destroys all audio data instantly.

### 5.2 Audio Capture Abstraction

```rust
pub trait MicrophoneCapture: Send + Sync {
    fn start(&self) -> Result<Receiver<AudioChunk>, AsrError>;
    fn stop(&self);
}

pub struct AudioChunk {
    pub data: Vec<i16>,     // PCM, 16kHz, mono
    pub timestamp: Instant,
}
```

Platform-specific implementations are conditionally compiled per target:
- **iOS:** `AVAudioEngine` with `AVAudioPCMBuffer` + Acoustic Echo Cancellation
- **Android:** `AudioRecord` with `RECORD_AUDIO` permission + AEC via `AudioEffect`

### 5.3 VAD Gating — The Power Budget Guardian

Silero VAD sits between the microphone and the ASR engine. When no speech is detected for ≥ 1.5 seconds, the heavy neural network (ASR model) is put to sleep. This means the transformer is only actively inferring for roughly 30–40 minutes out of a 3-hour sermon, reducing battery draw by ~60–70% compared to always-on transcription.

**VAD decision thresholds:**
- Speech confidence > 0.6 → wake ASR, start transcribing
- Silence for 1.5s → sleep ASR, keep VAD running
- Complete silence for 30s → notify UI ("Listening paused"), optionally dim screen further

### 5.4 ASR Engine — sherpa-onnx

Use the official `sherpa-onnx` Rust crate (safe bindings over the sherpa-onnx C++ core — no raw `-sys` layer). Model selection: streaming zipformer/transducer.

| Tier | Model | Size | Accuracy | Target Device |
|------|-------|------|----------|---------------|
| Standard | `zipformer-en-streaming` | ~80MB | High | Mid-to-high end |
| Compact | `zipformer-en-tiny-streaming` | ~30MB | Good | Low-end / 2GB RAM |
| Multilingual | `zipformer-multi-streaming` | ~150MB | High | High-end |

**Speaker Adaptation — Settled Decision:** No voice training is required for v1. The base zipformer model is speaker-independent and generalizes across accents, voices, and PA system acoustics without per-user enrollment. Speaker-specific fine-tuning (via residual adapters or custom ONNX model packs) is a post-launch optional enhancement — not a blocking dependency. No voice training UI or enrollment flow is to be built for the initial release.

Model files are downloaded as data packs, not embedded in the binary. Language can be switched at runtime by swapping the loaded model — no restart required.

### 5.5 Acoustic Echo Cancellation (AEC) — Required

PA systems create reverb and echo that confuses ASR models. The audio capture layer **must** enable platform-level AEC before feeding samples to sherpa-onnx:
- **Android:** `AudioEffect(EFFECT_TYPE_AEC)` via `AudioRecord` builder
- **iOS:** `AVAudioSession.CategoryOptions.defaultToSpeaker` + hardware AEC (implicit in `AVAudioEngine`)

Without AEC, a loud PA system will produce echo that the ASR interprets as doubled speech, causing false positives or misrecognitions.

### 5.6 Threading Model

```
Mic (OS thread) → VAD filter → ASR Engine → crossbeam_channel::Sender<String>
                                                        │
                                          ┌─────────────▼──────────────┐
                                          │  resolve_window()           │
                                          │  Rolling 15-word buffer     │
                                          │  Bible reference detector   │
                                          └─────────────┬──────────────┘
                                                        │ on match
                                          ┌─────────────▼──────────────┐
                                          │  VerseDetectedHandler       │
                                          │  callback → platform UI     │
                                          └────────────────────────────┘
```

- **AudioWorker** is a dedicated `std::thread` — it owns the `MicrophoneCapture` and `OnlineRecognizer`. No other thread touches these.
- Data flows one-way: Mic → VAD → ASR → channel. The UI never blocks Rust; Rust never blocks the UI.
- The `VerseDetectedHandler` callback fires on the `AudioWorker` thread. Marshaling onto the platform main thread before touching UI state is the **explicit responsibility** of the Swift/Kotlin implementation — not Rust or UniFFI.
  - Swift: `DispatchQueue.main.async { ... }`
  - Kotlin: `lifecycleScope.launch(Dispatchers.Main) { ... }`

## 6. Reference Parser (Grammar Engine)

### 6.1 Design: Deterministic Finite-State Machine

The parser is a pure FSM over a token stream. No ML, no NLP, no regex on the hot path. It is data-driven: all book names, aliases, and number-words come from compiled-in `phf::Map` tables.

- Book aliases load from a compile-time `phf::Map` generated by `bible-datagen` from per-language TOML files (`en_aliases.toml`, etc.) — never hardcoded per-language logic in `bible-core` itself.
- Number-words normalize via a lookup table (`"sixteenth"` → 16, `"first"` → 1), not regex.

### 6.2 Supported Input Patterns (minimum v1)

| Pattern | Example |
|---------|---------|
| `<Book> <Chapter>:<Verse>` | "John 3:16" |
| `<Book> <Chapter> <Verse>` | "Genesis 1 1" |
| `<Ordinal> <Book> <Chapter>:<Verse>` | "First Corinthians 13:4" |
| `<Ordinal> <Book> <Chapter> verse <Verse>` | "Second Timothy chapter 2 verse 15" |
| Noisy prefix | "…and you'll find that in John 3:16…" (rolling window catches it) |

### 6.3 Rolling Window Matching

`resolve_window(words: &[String]) -> Option<VerseRef>` runs on a rolling buffer of the last 15–20 words from the ASR transcript. It returns:
- `Some(VerseRef)` — immediately on a definitive, unambiguous match
- `None` — if the pattern is incomplete or ambiguous (never guesses)

After a successful match, the window is reset (debounce: 3 seconds) to prevent the same verse firing multiple times while the pastor finishes his sentence.

### 6.4 False Positive Prevention

The parser only triggers on **complete structured patterns** — a book name is meaningless without a chapter and verse number. This prevents:
- Pastor saying "John" as a person's name → no number follows → `None`
- Congregation shouting "Amen" → no book pattern → `None`
- Partial references ("turn to John…" + pause) → window holds, waits for number
- Interrupted references ("John 3… actually let's go to Romans") → window resets when "Romans" is seen as a new book token

### 6.5 Testing Requirements

- **Example-based unit tests:** 100+ hand-written variations per language
- **Property-based tests (`proptest`):** Generate random valid phrasings per pattern — catches edge cases hand-written examples miss
- **Fuzzing (`cargo fuzz`):** Adversarial inputs (long strings, malformed Unicode, overlapping aliases, very long books)

## 7. FFI Contract (bible-ffi)

`bible-ffi` is the only public surface, using proc-macro syntax (`#[uniffi::export]`). `BibleEngine` must be `Send + Sync`.

### 7.1 Required Exposed Methods

```rust
// Lookup
pub fn lookup(translation: String, book: String, chapter: u16, verse: u16) -> Result<String, EngineError>

// Parser
pub fn resolve_spoken(language: String, text: String) -> Result<VerseRef, EngineError>

// Sermon Mode
pub fn start_sermon_mode(language: String, handler: Arc<dyn VerseDetectedHandler>) -> Result<(), EngineError>
pub fn stop_sermon_mode() -> Result<(), EngineError>

// Translation management
pub fn load_translation(path: String) -> Result<(), EngineError>
pub fn unload_translation(code: String) -> Result<(), EngineError>
pub fn list_loaded_translations() -> Vec<String>

// Versioning
pub fn version() -> String   // semver, checked against pack headers
```

### 7.2 Callback Contract

```rust
#[uniffi::export(with_foreign)]
pub trait VerseDetectedHandler: Send + Sync {
    fn on_verse_detected(&self, verse: VerseRef) -> Result<(), CallbackError>;
    fn on_listening_state_changed(&self, is_active: bool) -> Result<(), CallbackError>;
    fn on_asr_error(&self, error: String) -> Result<(), CallbackError>;
}
```

Callback methods return `Result<(), CallbackError>`, not bare `()`. A foreign-side failure with no `Result` will panic across the FFI boundary.

### 7.3 Error Enum

```rust
#[derive(uniffi::Error, thiserror::Error)]
pub enum EngineError {
    #[error("Translation '{0}' not found")]
    TranslationNotFound(String),

    #[error("Verse {book} {chapter}:{verse} not found")]
    VerseNotFound { book: String, chapter: u16, verse: u16 },

    #[error("Data pack for '{translation}' is corrupt")]
    CorruptDataPack { translation: String },

    #[error("Pack version {found} unsupported (expected {expected})")]
    UnsupportedPackVersion { found: u32, expected: u32 },

    #[error("ASR model load failed: {0}")]
    ModelLoadFailed(String),

    #[error("Microphone permission denied")]
    MicrophonePermissionDenied,

    #[error("Already in Sermon Mode")]
    AlreadyListening,

    #[error("Not currently listening")]
    NotListening,

    #[error("Audio device unavailable: {0}")]
    AudioDeviceUnavailable(String),
}
```

## 9. Device Behavior & Real-World Runtime Design

### 9.1 Long Session Operation (2–3 Hour Sermons)

The app is designed for sustained foreground use during services. Key behaviors:

**Power Management:**
- Request a **Partial Wake Lock** (Android) / set `UIApplication.shared.isIdleTimerDisabled = true` (iOS) in Sermon Mode. The screen may dim but must not lock — if the screen locks, the OS throttles the CPU and the neural network latency spikes beyond 200ms.
- VAD gating reduces active ASR inference to ~30–40 minutes out of a 3-hour session. The mic itself remains live (cheap) while the transformer is idle.
- Recommend to users: plug the device in during long services. A 3-hour always-on session with VAD gating consumes ~20–25% battery on a modern mid-range phone.

**Thermal Management:**
- On sustained high CPU load (neural net + audio processing), ARM chips throttle frequency. If the device thermal state rises above nominal, the app may automatically switch to the Compact model tier (30MB zipformer) to reduce inference time and heat.
- Monitor thermal state via platform APIs (`ProcessInfo.thermalState` on iOS, thermal headroom APIs on Android 12+).

**Memory:**
- The ring buffer is ~320KB. Each loaded translation is ~30–80MB mmap'd (RSS shared with OS, not counted as private memory). Total app memory footprint: ~150–250MB depending on model size.

### 9.2 Screen State & Display Activation

- **Screen must stay on** during Sermon Mode. The app does not "wake" the screen when a verse is detected — waking a locked screen takes 200–400ms and defeats the <200ms latency target.
- Recommended UX: screen remains dimly lit at minimum brightness. On verse detection, the UI brightens immediately and displays the text. No lock/unlock cycle.
- If the user intentionally locks the phone, Sermon Mode should pause with a clear status indicator (e.g., notification: "Sermon Mode paused — tap to resume").

### 9.3 Performance Across Hardware Classes

| Hardware Class | Example Devices | ASR Latency | Strategy |
|----------------|----------------|-------------|----------|
| High-end | iPhone 15 Pro, Pixel 9 Pro, Galaxy S25 | ~80–100ms | Standard model; NPU acceleration via ONNX runtime |
| Mid-range | iPhone 13, Pixel 7a, Galaxy A55 | ~120–160ms | Standard model; CPU ARM NEON fallback |
| Low-end | 2GB RAM Android, older iPhones | ~200–350ms | Force Compact model; alert user if consistently >200ms |

The verse **lookup** (mmap + phf) is hardware-agnostic: always < 100µs regardless of chip class. The bottleneck is exclusively in ASR inference.

### 9.4 Background Behavior

- **iOS:** The iOS background audio entitlement (`audio` background mode) is required for the mic to remain active when the screen dims. Without it, the OS silences the microphone immediately. This entitlement requires Apple App Store justification.
- **Android:** A foreground service with an ongoing notification is required to keep the AudioRecord stream alive when the app moves to the background. The notification should clearly state "Sermon Mode Active — listening for Bible references."
- If background mic access is revoked by the OS (e.g., another app takes the mic, or the user denies it), the app must gracefully return `EngineError::AudioDeviceUnavailable` and display a recoverable error — not crash.

## 10. Edge Cases & Scenario Catalog

The following real-world scenarios have been analyzed and the engine must handle all of them:

### 10.1 Partial or Interrupted References
**Scenario:** Pastor says "Turn to John... [2-second pause] ...chapter 3... [1-second pause] ...verse 16."
**Behavior:** The rolling window retains "John" as a book token. When "chapter 3" arrives, the window state progresses. When "verse 16" arrives, the full pattern is complete → `Some(John 3:16)`. The inter-word gap tolerance in the rolling window must be at least 5 seconds.

### 10.2 The "John" Name Trap
**Scenario:** Pastor says "And John the Baptist said unto them..."
**Behavior:** "John" is recognized as a book alias, but no numeric pattern follows. The window remains open but returns `None`. After 5 seconds with no numbers, the window resets silently. No false detection.

### 10.3 Multiple Verses in One Sentence
**Scenario:** Pastor says "As we see in John 3:16 and also in Romans 8:28..."
**Behavior:** John 3:16 is matched and fired. The window debounce timer starts (3 seconds). "Romans 8:28" arrives within the debounce window → treated as a second event. Fire both with a short delay (500ms between callbacks). The platform UI must handle receiving multiple verse callbacks in quick succession gracefully.

### 10.4 Overlapping Congregation Speech
**Scenario:** Congregation simultaneously says the verse aloud while the pastor reads it.
**Behavior:** The ASR model receives a mixed signal. If the signal is sufficiently garbled, the confidence score drops below threshold → transcript segment is discarded or produces garbage tokens → no match → `None`. This is acceptable behavior. Silero VAD's confidence threshold should be tuned so that muffled crowd speech is gated out. AEC helps significantly here.

### 10.5 PA System Feedback / Reverb
**Scenario:** The pastor's voice echoes back through the PA system into the device microphone.
**Behavior:** AEC (§5.5) is non-negotiable in this environment. Without it, the echo creates doubled ASR output. With AEC enabled, the echo is cancelled before the sample reaches the VAD.

### 10.6 Language Switching Mid-Sermon
**Scenario:** Pastor switches from English to Yoruba or Pidgin mid-service.
**Behavior:** The app uses whichever language model the user selected before starting Sermon Mode. It does not auto-detect language switches. If a multilingual model is loaded, it will attempt to transcribe in the detected language with reduced accuracy. Language ID (automatic detection) is a post-launch enhancement — for v1, the user selects the language manually before starting.

### 10.7 Low Battery / Power-Saving Mode
**Scenario:** Device battery drops below 20% and Android/iOS enable aggressive battery saver mode.
**Behavior:** Battery saver mode typically limits background CPU, reduces screen brightness, and may kill foreground service CPU priority. The app should:
1. Detect battery saver activation and warn the user.
2. Automatically switch to the Compact ASR model to reduce CPU load.
3. Lower the VAD sensitivity threshold to gate more aggressively.
4. If device drops below 10%, prompt the user to plug in or pause Sermon Mode.

### 10.8 Model Not Downloaded
**Scenario:** User activates Sermon Mode without having downloaded an ASR model.
**Behavior:** `start_sermon_mode` returns `EngineError::ModelLoadFailed("No model found for language 'en'")`. The platform UI must direct the user to the model download screen. Sermon Mode cannot function without a model — no silent degradation.

### 10.9 Translation Pack Missing
**Scenario:** User selects a translation that hasn't been downloaded yet.
**Behavior:** `lookup(...)` returns `EngineError::TranslationNotFound("NIV")`. The platform UI presents a download prompt. The app must never attempt to display partial or cached results from a missing pack.

### 10.10 Corrupted or Truncated Data Pack
**Scenario:** A data pack was partially downloaded or the file was corrupted.
**Behavior:** On first load, BLAKE3 checksum fails → `EngineError::CorruptDataPack { translation }`. The app must prompt the user to re-download the pack. The corrupted file should be deleted automatically to free storage.

### 10.11 Device Rotation / App Lifecycle Events
**Scenario:** User rotates the device mid-sermon or the OS sends the app to background and returns it to foreground.
**Behavior:**
- The `AudioWorker` thread is independent of the UI lifecycle. Rotation does not interrupt listening.
- On background → foreground transition: re-check mic permission and audio session state. If the audio session was interrupted (e.g., a phone call), resume automatically after the interruption ends (iOS: `AVAudioSession.InterruptionType.ended` notification).

### 10.12 Simultaneous App (Phone Call Interruption)
**Scenario:** A phone call arrives during a sermon.
**Behavior:** The OS takes over the audio session. Sermon Mode must:
1. Detect the audio session interruption.
2. Stop the `AudioWorker` gracefully.
3. Notify the UI via `on_listening_state_changed(false)`.
4. When the call ends, automatically resume if the user had not manually stopped Sermon Mode.

### 10.13 Aliased Book Names (Cross-Language / Abbreviations)
**Scenario:** Pastor uses a non-standard abbreviation ("1 Cor", "Gal", "Phil") instead of the full name.
**Behavior:** All standard abbreviations for all 66 books (and their ordinal forms) are compiled into the alias tables from `en_aliases.toml`. This covers at minimum: full names, standard abbreviations (USFM codes), common spoken forms, ordinal forms ("First Timothy", "1st Timothy", "1 Tim"), and common mis-abbreviations. The alias table must be reviewed by a domain expert familiar with how pastors actually speak in different traditions.

### 10.14 Very Long or Malformed Input to Parser
**Scenario:** A transcript segment arrives with 500+ words or contains malformed Unicode, null bytes, or deeply nested numbers.
**Behavior:** `resolve_text` and `resolve_window` are both bounded by the ring buffer size (max 20 words). Any input over this limit is silently truncated before parsing. The FSM has no backtracking — worst-case parsing is O(n) on the bounded buffer. Malformed Unicode is handled at the tokenizer layer (normalization to valid UTF-8 before FSM entry). No panic, no crash.

| Operation | Target | Test Environment |

- `resolve_window` parsing: ~1ms

- FFI + platform callback: ~5ms
- UI render (platform): ~10ms

## 13. Exclusions — Explicit Bans

| What | Why |
|------|-----|
| `unsafe` beyond mmap + FFI boundary | Safety; every `unsafe` block needs an inline invariant comment |
| SQLite, LMDB, or embedded databases | Not needed; `rkyv` + `phf` are sufficient and faster |
| `serde_json` / `protobuf` on hot path | Too slow; use `rkyv` only |
| `tokio` / `async-std` in `bible-core` / `bible-asr` | Breaks determinism; use `std::thread` + channels |
| `static mut` | All state lives in `BibleEngine` |
| Recording audio to disk | Privacy-by-design; ring buffer only |
| Voice training / speaker enrollment | Not needed; speaker-independent model; post-launch optional |
| GPL/AGPL dependencies without explicit sign-off | License risk in commercial distribution |
| `cargo-lipo` for iOS | Deprecated; use XCFramework |
| Git commits without user permission | Per project rules |
